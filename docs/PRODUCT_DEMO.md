---

## 1. Safety & Data Privacy Rules

1. **Zero Production Data:** All screenshots and video recordings must use purely synthetic/seeded clinic records. Never use real patients, real phone numbers, real medical records, or live WhatsApp chats.
2. **Deterministic Seed Data:** Fictional Indian names, reserved demo email domains, and non-routable demo phone numbers are generated by `scripts/seed-demo-clinic.ts`.
3. **No Mockups or AI-Generated Placeholders:** Every image must be captured directly from a running authenticated application.
4. **Environment Guard:** Seed and reset commands require `DEMO_MODE=true`, a `local` or `staging` environment, and an exact account-ID confirmation. The harness rejects the production Helpa hostname.
5. **No Outcome Pollution:** Seeded rows carry the `helpa-product-demo-v1` marker and synthetic metadata. The harness creates no product-outcome events.
6. **Resolution & Optimization:** Screenshots are captured at native `1440×900` resolution with animations disabled and text kept crisp.

---

## 2. Automated Demo Workflow

Use a dedicated staging tenant and an existing owner/admin user. Never reuse a production clinic account.

```bash
cp .env.local.example .env.local
# Configure Supabase, DEMO_ACCOUNT_ID, DEMO_USER_ID, and the exact
# DEMO_CONFIRM_ACCOUNT_ID. For staging set DEMO_ENVIRONMENT=staging.
DEMO_MODE=true npm run demo:seed
npm run build
DEMO_CAPTURE=true npm run demo:capture
```

The capture test writes the seven reviewable images to `public/assets/screenshots/`. After capture, inspect each image before publishing it.

To remove only the stable fixture records created by the harness:

```bash
DEMO_MODE=true npm run demo:reset
```

### Required environment values

- `DEMO_MODE=true`
- `DEMO_ENVIRONMENT=local` or `staging`
- `DEMO_ACCOUNT_ID` — dedicated synthetic tenant UUID
- `DEMO_USER_ID` — active owner/admin auth user UUID in that tenant
- `DEMO_CONFIRM_ACCOUNT_ID` — exact repeat of the target account UUID
- `DEMO_EMAIL` / `DEMO_PASSWORD` — browser login for screenshot capture
- `PLAYWRIGHT_TEST_BASE_URL` — staging URL for remote capture
- `DEMO_REFERENCE_DATE` — optional `YYYY-MM-DD` anchor for repeatable dates

## 5. Acceptance Criteria

- The seed command is idempotent and updates stable fixture IDs instead of creating duplicates.
- Seed/reset fail closed unless the target environment and account are explicitly confirmed.
- A supplied demo user must already be an active member of the synthetic tenant.
- Normal `npm run test:e2e` skips evidence capture unless `DEMO_CAPTURE=true`.
- All seven files are captured at `1440×900` from the authenticated application.
- Images contain only the three documented fictional patients and demo clinic data.
- The final video is 85–95 seconds at 1080p and includes captions.
- A human reviews every generated asset before it is published.
