# Canonical Deployment Architecture & Single Source of Truth

**Production Domain**: `https://www.helpa.studio`  
**Authoritative Backend & Site Host**: Appwrite Cloud (Region: `sgp`, Project ID: `6a79822b003adde92f63`, Database: `helpa_main`)  
**Production Branch**: `main`  
**Build Command**: `npm run build` (`next build --webpack`)  
**Runtime**: Next.js 16 (Node.js 22 LTS / Appwrite Sites runtime)

---

## 1. Authoritative Production Target

The single source of truth serving `https://www.helpa.studio` is:

- **Provider**: Appwrite Sites (Edge SGP Cluster)
- **Domain Assignment**: `www.helpa.studio` -> `https://sgp.cloud.appwrite.io/v1`
- **Database Engine**: Appwrite Databases (`helpa_main`)
- **Storage Engine**: Appwrite Storage (`chat-media`, `lab-reports`, `medical-records`)

### Disambiguation of Secondary Targets

- **Vercel Previews (`wacrm`, `wacrm_susanta`)**:
  - Legacy preview targets are non-canonical for production routing.
  - Vercel preview environments must not be used to gate production verification or override custom domain branch protections.
  - Required GitHub branch protections must gate only canonical CI checks (`Production Quality & Security Gates`).

## 2. Commit SHA Resolution & Mapping

The live `/api/health` endpoint strictly resolves deployment identity in the following documented priority:

1. `APP_COMMIT_SHA` (Explicit container build-time / server-injected commit)
2. `VERCEL_GIT_COMMIT_SHA` (Vercel deployment environment)
3. `GITHUB_SHA` (GitHub Actions workflow context)
4. `SOURCE_VERSION` (Container engine / Appwrite Sites runtime variable)
5. `NEXT_PUBLIC_COMMIT_SHA` (Inlined build-time fallback generated by `next.config.ts`)
6. `src/lib/build-info.json` (Local build artifact generated during `npm run build`)

All resolved values are normalized to lowercase and validated against `/^[0-9a-f]{40}$/`.

---

## 3. Post-Deployment Verification Pipeline

Post-deployment verification is managed by [`.github/workflows/post-deploy.yml`](file:///.github/workflows/post-deploy.yml) and [`scripts/verify-deployment.mjs`](file:///scripts/verify-deployment.mjs):

1. Polls `https://www.helpa.studio/api/health?_t=<timestamp>` with cache-busting headers.
2. Extracts `.commit` and asserts `DEPLOYED_SHA === EXPECTED_SHA`.
3. Validates database and Appwrite API connectivity (`checks.database === "healthy"`).
4. Fails with non-zero exit code if a SHA mismatch, malformed SHA, or 10-minute timeout occurs.
5. Emits redacted verification evidence to `artifacts/deployment-verification.json`.
